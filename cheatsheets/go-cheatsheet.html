Go glossary

the words people throw around, in plain language
module
A collection of related packages versioned together, defined by a go.mod file. The unit you publish and depend on.
package
A directory of .go files compiled together. package main with a main() is an executable; others are libraries.
go.mod / go.sum
The module's name and dependency list / the checksums that verify those dependencies haven't changed.
goroutine
A function running concurrently, managed by the Go runtime. Far lighter than an OS thread — you can have thousands.
channel
A typed pipe used to send and receive values between goroutines safely.
slice
A flexible, growable view over an array — the everyday list type in Go.
map
A built-in hash table mapping keys to values.
struct
A typed grouping of named fields — Go's main way to model data.
interface
A set of method signatures. Any type with those methods satisfies it automatically — no “implements” keyword.
pointer
Holds the memory address of a value. &x takes an address, *p reads through one.
rune
A Unicode code point — an alias for int32.
byte
A single 8-bit value — an alias for uint8.
zero value
The default a variable gets with no initializer: 0, false, "", or nil. There are no uninitialized values in Go.
defer
Schedules a call to run when the surrounding function returns — used for cleanup like closing files.
panic / recover
Go's abort-and-catch mechanism for truly exceptional cases — not for everyday error handling.
error
The built-in interface for failures. Functions return errors as ordinary values you check.
nil
The zero value for pointers, slices, maps, channels, interfaces, and functions.
receiver
The value a method is attached to, written before the method name: func (r T) M().
vendoring
Copying dependencies into a vendor/ folder so builds need no network.
workspace (go.work)
A way to develop several local modules together as one.
GOOS / GOARCH
The target operating system and CPU architecture, set to cross-compile binaries.
