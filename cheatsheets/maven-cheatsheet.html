Maven glossary

the build-tool words people throw around, in plain language
POM (pom.xml)
The Project Object Model — the XML file that describes your project: its coordinates, dependencies, plugins, and build config.
coordinates (GAV)
The groupId, artifactId, and version that uniquely identify an artifact, e.g. com.example:my-app:1.0.0.
groupId
Your organization namespace, usually a reverse domain like com.example.
artifactId
The project's own name within the group, like my-app.
packaging
What the build produces: jar (default), war, pom (for aggregator/parent projects), and more.
lifecycle
An ordered series of build phases. The default one runs validate → compile → test → package → verify → install → deploy.
phase
One step in a lifecycle. Asking for a phase runs it and every phase before it.
goal
A specific task a plugin performs, like compiler:compile. Phases are made of bound goals.
plugin
A bundle of goals. Almost everything Maven does is actually a plugin doing the work.
dependency
Another artifact your project needs, declared by its coordinates in the POM.
scope
When a dependency is available: compile, provided, runtime, test, system, or import.
transitive dependency
A dependency pulled in indirectly — your dependency's own dependencies.
SNAPSHOT
An in-development version (e.g. 1.0.0-SNAPSHOT). Maven may re-fetch it for the latest build.
local repository
The ~/.m2/repository cache on your machine where downloaded and installed artifacts live.
central / remote repo
Maven Central and other servers Maven downloads dependencies from and deploys to.
archetype
A project template used by archetype:generate to scaffold a new project.
BOM
A “bill of materials” POM you import to manage a set of dependency versions consistently.
profile
A named set of build settings you switch on/off, e.g. for dev vs prod, activated with -P.
effective POM
Your POM after inheritance, defaults, and profiles are merged in — what Maven really uses.
reactor
Maven's engine for multi-module builds; it works out the right order to build modules.
wrapper (mvnw)
Scripts checked into the project that run a pinned Maven version, so everyone builds the same way.
settings.xml
Your personal Maven config (in ~/.m2) for things like mirrors, proxies, and server credentials.
