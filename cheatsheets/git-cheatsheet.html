Git glossary

the words people throw around, in plain language
HEAD
A pointer to “where you are right now” — usually the tip of your current branch.
detached HEAD
HEAD is sitting on a specific commit instead of a branch. New commits here belong to no branch and can be lost. Make a branch to keep them.
working tree
Your actual files on disk — what you edit in your editor.
staging area (index)
A holding area for changes you’ve marked with git add, waiting to go into the next commit.
commit
A saved snapshot of your project at a point in time, with a unique ID (hash).
branch
A movable label pointing to a commit — effectively a separate line of work.
main / master
The default primary branch. “master” is the older name; “main” is the modern default.
remote
A hosted copy of the repo, e.g. on GitHub, that you sync with.
origin
The default nickname for the remote you cloned from.
upstream
The remote branch your local branch is linked to and tracks.
fetch
Download new commits from the remote without changing your files yet.
fast-forward
A merge so simple Git just slides the branch pointer forward — no merge commit needed.
merge commit
A special commit that joins two branches together.
rebase
Re-applying your commits on top of a different base, to keep history a straight line.
HEAD~1 / HEAD^
Shorthand for ancestors: HEAD~1 is the commit just before HEAD, HEAD~2 two before, and so on.
stash
A shelf where you temporarily store uncommitted changes.
tag
A fixed label on a commit, usually marking a release version.
tracked / untracked
Whether Git is currently watching a file. New files are untracked until you git add them.
ref
Any name that points to a commit — branches, tags, and HEAD are all refs.
hash (SHA)
The unique fingerprint ID of a commit, like a1b2c3d.
