Program structure

// tsconfig.json
{
  "compilerOptions": {
    "strict": true,
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "noUncheckedIndexedAccess": true
  }
}
npm install --save-dev typescript tsx
npx tsc --init
npx tsc                    # type-check and emit JavaScript
npx tsx src/main.ts        # run TypeScript directly
  • TypeScript compiles to JavaScript. Types are erased and do not exist at runtime.
  • Use strict in tsconfig.json; it enables null checks and other safety rules.
  • Source files use .ts or .tsx; declarations use .d.ts.
  • Types catch mistakes at build time. They do not validate JSON or user input at runtime.

Variables & inference

const name = "Ada";             // literal type "Ada"
let age = 36;                   // number
const ids = [1, 2] as const;    // readonly [1, 2]
let user: { name: string; age?: number } = { name: "Ada" };

const el = document.querySelector("#app")!;  // non-null assertion
const value = input as string;               // assertion, no runtime check

const config = { mode: "dark" } satisfies Config; // 4.9+
// config.mode is "dark", and Config is checked
  • Prefer const; use let only when reassigning. Avoid var.
  • TypeScript infers local types. Annotate public function boundaries and empty collections.
  • as and ! are assertions, not validation. They can hide runtime failures.
  • satisfies checks a value against a type without widening its inferred literal type.

Narrowing & unions

function format(value: string | number | null): string {
    if (value === null) return "";
    if (typeof value === "number") return value.toFixed(2);
    return value.toUpperCase();
}

type Shape =
    | { kind: "circle"; r: number }
    | { kind: "square"; s: number };

function area(shape: Shape): number {
    switch (shape.kind) {
        case "circle": return Math.PI * shape.r ** 2;
        case "square": return shape.s ** 2;
        default: {
            const exhaustive: never = shape;
            return exhaustive;
        }
    }
}
  • Narrow with typeof, in, instanceof, equality and truthiness.
  • A discriminated union needs a shared literal field, usually kind or type.
  • The never assignment proves every case is handled.
  • Prefer === to ==; loose equality performs coercion.

Strings & templates

const s = "TypeScript";
s.length;                 // 10
s.toUpperCase();          // "TYPESCRIPT"
s.slice(0, 4);            // "Type"
s.includes("Script");     // true

const who = "Ada";
`${who} has ${s.length} characters`; // "Ada has 10 characters"

type Route = `/users/${string}`;     // template literal type
const legacy = String.raw`C:	empile`; // backslashes preserved
  • Strings are immutable UTF-16 sequences. There is no separate character type.
  • Template literals interpolate with ${...} and can span multiple lines.
  • Template literal types model string patterns at compile time.
  • Use String() or a template literal for conversion; avoid relying on + with mixed types.

Control flow

if (ok) {
    // ...
} else if (fallback) {
    // ...
} else {
    // ...
}

switch (status) {
    case "ok":
        break;
    case "error":
        throw new Error("failed");
    default:
        break;
}

for (const item of items) { }
for (const key in obj) {
    if (!Object.hasOwn(obj, key)) continue;
}

while (cond) { }
do { } while (cond);

try {
    risky();
} catch (error: unknown) {
    if (error instanceof Error) console.error(error.message);
} finally {
    cleanup();
}
  • for...of iterates values; for...in iterates enumerable keys.
  • switch falls through until break; return or break deliberately.
  • catch is unknown under strict settings; narrow before reading properties.
  • Object.hasOwn is safer than the in operator for own-property checks.

Arrays & tuples

const names: string[] = ["a", "b"];
const matrix: number[][] = [[1, 2], [3, 4]];
const pair: [string, number] = ["a", 1];
const optional: [string, number?] = ["a"];
const rest: [string, ...number[]] = ["a", 1, 2];
const readonlyNames: readonly string[] = ["a"];

names.push("c");
names.map((name) => name.toUpperCase());
const [first, second] = pair;       // string, number
const literal = ["a", 1] as const;  // readonly ["a", 1]
  • Arrays are homogeneous. Tuples have a fixed shape and positional types.
  • readonly arrays prevent mutation at compile time; it is shallow.
  • noUncheckedIndexedAccess makes arr[0] possibly undefined. Handle it.
  • as const preserves literal and readonly modifiers in the inferred type.

Objects & interfaces

interface User {
    id: number;
    name: string;
    email?: string;
    readonly createdAt: Date;
}

type Point = { x: number; y: number };
type Scores = Record<string, number>;

const user: User = {
    id: 1,
    name: "Ada",
    createdAt: new Date(),
};
user.name = "Grace";
// user.id = 2;            // error: readonly

const point: Point = { x: 1, y: 2 };
  • interface can be extended and merged; type is better for unions and mapped types.
  • ? means the property may be absent; readonly is compile-time only.
  • Object literals get excess-property checks; a variable with extra fields can still be assignable structurally.
  • Index signatures such as Record<string, number> describe dynamic keys.

Functions

function add(a: number, b: number): number {
    return a + b;
}
const mul = (a: number, b: number): number => a * b;

function greet(name: string, greeting = "Hello"): string {
    return `${greeting}, ${name}`;
}
function sum(...nums: number[]): number {
    return nums.reduce((total, n) => total + n, 0);
}

type Handler = (event: Event) => void;
const onClick: Handler = (event) => console.log(event.type);

function parse(value: string): string;
function parse(value: number): number;
function parse(value: string | number) { return value; }
  • Annotate parameters and public return types; infer local return types.
  • Optional parameters use ?; default parameters are already optional.
  • Overloads describe multiple call signatures, with one implementation signature.
  • Functions are values; a function type is written (arg: T) => R.

Classes

class User {
    readonly id: number;
    private email: string;
    #token: string;

    constructor(id: number, email: string, token: string) {
        this.id = id;
        this.email = email;
        this.#token = token;
    }

    get contact(): string { return this.email; }
    greet(): string { return `User ${this.id}`; }
}

class Admin extends User {
    constructor(
        id: number,
        email: string,
        token: string,
        public level: number,
    ) {
        super(id, email, token);
    }
    override greet(): string { return `Admin ${this.level}`; }
}
  • private is compile-time only; #field is runtime-private.
  • Parameter properties such as public level declare and assign a field.
  • readonly can be assigned in the constructor only; override catches base-class drift.
  • Use abstract for a base that must be subclassed and cannot be instantiated.

Unions & intersections

type Status = "idle" | "loading" | "error";
type Result<T> =
    | { ok: true; value: T }
    | { ok: false; error: string };

type Admin = User & { level: number };

function handle<T>(result: Result<T>): void {
    if (result.ok) {
        console.log(result.value);
    } else {
        console.error(result.error);
    }
}
  • A union means one of the alternatives; narrow before using alternative-specific fields.
  • An intersection combines requirements; A & B must satisfy both.
  • Discriminated unions plus never give exhaustive, type-safe branching.
  • Use keyof to turn object keys into a union of string literals.

Generics

function first<T>(items: T[]): T | undefined {
    return items[0];
}

function pick<T, K extends keyof T>(obj: T, key: K): T[K] {
    return obj[key];
}

type Box<T> = { value: T };
const box: Box<string> = { value: "x" };

function tuple<T extends readonly unknown[]>(...args: T): T {
    return args;
}
const pair = tuple("a", 1); // [string, number]

Const type parameters 5.0+

function literals<const T extends readonly string[]>(...values: T): T {
    return values;
}
const modes = literals("light", "dark"); // readonly ["light", "dark"]
  • Generics preserve the relationship between input and output types.
  • Constraints use extends; defaults use =.
  • Use keyof, typeof and indexed access to derive types from values.
  • const type parameters preserve literal types without requiring as const at the call site.

Utility types

Exclude<T, U>union members assignable to U removed
Extract<T, U>union members assignable to U kept
ReturnType<F>the return type of a function
Parameters<F>the parameter tuple of a function
NonNullable<T>T without null and undefined

type UserPatch = Partial<User>;
type PublicUser = Omit<User, "email">;
type ById = Record<number, User>;
type Fn = (x: string) => number;
type R = ReturnType<Fn>;        // number
type P = Parameters<Fn>;        // [x: string]

Utility types are built from mapped and conditional types. They are erased like every other type.

Enums & literal objects

enum Direction { Up, Down }
enum Role { Admin = "ADMIN", User = "USER" }

const Colors = {
    Red: "#f00",
    Blue: "#00f",
} as const;

type Color = typeof Colors[keyof typeof Colors];
const red: Color = Colors.Red;
  • Numeric enums are reverse-mapped and emit runtime code. String enums are easier to debug.
  • const enum is inlined and can break under isolated modules or declaration emit; prefer a const object.
  • For a small fixed set, a union of string literals is often simpler than an enum.
  • typeof Colors[keyof typeof Colors] derives the union of the object's values.

Async & promises

async function load(id: string): Promise<User> {
    const res = await fetch(`/api/users/${id}`);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return (await res.json()) as User;
}

const [a, b] = await Promise.all([load("1"), load("2")]);
const first = await Promise.race([load("1"), load("2")]);

try {
    await load("3");
} catch (error: unknown) {
    const message = error instanceof Error ? error.message : "unknown";
    console.error(message);
}
  • async functions always return a Promise; await unwraps one.
  • Promise.all fails fast; Promise.allSettled waits for every result.
  • Do not leave promises floating. Await, return, or attach a catch handler.
  • Use AbortController for cancellation and a timeout; a promise has no built-in timeout.

Modules & declarations

import { readFile } from "node:fs/promises";
import type { User } from "./types.js";
export type { User };
export const VERSION = "1.0";

export default class Client {
    constructor(private readonly baseUrl: string) {}
}

// declarations.d.ts
declare module "legacy-lib" {
    export function run(input: string): void;
}
  • import type is erased and avoids a runtime import.
  • With NodeNext, relative ESM imports include the emitted .js extension.
  • .d.ts files describe types for JavaScript or external packages.
  • Prefer ES modules. export = and import = require() are legacy CommonJS forms.

Common gotchas

  • any spreads silently through a codebase. Use unknown at boundaries and narrow.
  • == coerces types; use === unless you deliberately want coercion.
  • Object.keys(obj) is typed as string[], not keyof typeof obj.
  • readonly is shallow; a readonly array can still contain mutable objects.
  • Enums and const enum have runtime or build-mode caveats; const objects are often simpler.
  • as does not validate JSON. Use a runtime schema at the boundary.
  • An optional property (x?: T) and x: T | undefined differ under exactOptionalPropertyTypes.
  • Structural typing can accept extra fields through a variable even when an object literal would be rejected.
